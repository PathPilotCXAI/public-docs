Webhooks let your systems react to PathPilot events in real time. When a subscribed event occurs in your workspace — a control status changes, a workflow run finishes, a new user is invited — PathPilot sends an HTTP `POST` request to the URL you register, containing a JSON payload that describes the event. Use webhooks to trigger downstream automation without polling the API.

## Supported Events

Subscribe to any combination of the following event types when creating a webhook. Each event fires at most once per qualifying occurrence.

| Event Type               | Fired when...                                                        |
|--------------------------|----------------------------------------------------------------------|
| `control.status_changed` | A control transitions between statuses (e.g., from `in_progress` to `passing`). |
| `evidence.uploaded`      | A new piece of evidence is uploaded to any control in your workspace. |
| `workflow.run_completed` | A workflow run finishes, whether it succeeded or failed.             |
| `user.invited`           | A new user invitation is sent from your workspace.                   |
| `user.removed`           | A user is removed from your workspace.                               |
| `report.generated`       | A report finishes generating and is available for download.          |

## Webhook Payload Format

Every webhook request PathPilot sends contains a consistent JSON payload with a top-level `event` field, a `created_at` timestamp, and a `data` object whose structure depends on the event type.

```json
{
  "event": "control.status_changed",
  "created_at": "2024-01-15T10:30:00Z",
  "data": {
    "control_id": "ctrl_abc123",
    "previous_status": "in_progress",
    "new_status": "passing"
  }
}
```

PathPilot delivers webhook requests with a 10-second timeout. If your endpoint does not respond with a `2xx` status code within that window, PathPilot considers the delivery a failure and retries with exponential backoff up to 3 times over the following hour.

## Verifying Webhook Signatures

PathPilot signs every webhook payload using HMAC-SHA256 so you can verify that requests genuinely originate from PathPilot and have not been tampered with in transit. The signature is included in the `X-PathPilot-Signature` request header as a hex-encoded string.

To verify a signature, compute the HMAC-SHA256 of the raw request body bytes using your webhook secret, then compare it to the value in the header. Always use a constant-time comparison function to prevent timing attacks.

```python webhook_handler.py
import hmac
import hashlib

def verify_signature(payload_bytes, signature_header, secret):
    expected = hmac.new(
        secret.encode(),
        payload_bytes,
        hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(expected, signature_header)
```

Call this function before processing any event:

```python webhook_handler.py
from flask import Flask, request, abort

app = Flask(__name__)
WEBHOOK_SECRET = "your_webhook_secret_here"

@app.route("/webhooks/pathpilot", methods=["POST"])
def handle_webhook():
    signature = request.headers.get("X-PathPilot-Signature", "")
    
    if not verify_signature(request.data, signature, WEBHOOK_SECRET):
        abort(403)
    
    event = request.json
    # Process the verified event
    print(f"Received event: {event['event']}")
    return "", 200
```

<Warning>
  Always verify the `X-PathPilot-Signature` header before processing a webhook payload. Skipping signature verification leaves your endpoint open to spoofed requests from malicious third parties. Never act on a webhook payload — creating records, changing state, or sending notifications — until the signature check passes.
</Warning>

## List Webhooks

Retrieve all webhooks registered in your workspace.

```http
GET /v1/webhooks
```

### Example Request

```bash
curl https://api.pathpilot.com/v1/webhooks \
  -H "Authorization: Bearer pp_live_xxxxxxxxxxxx"
```

### Example Response

```json
{
  "data": [
    {
      "id": "wbh_4kRp7nQm",
      "url": "https://your-app.example.com/webhooks/pathpilot",
      "events": ["control.status_changed", "workflow.run_completed"],
      "status": "active",
      "created_at": "2024-01-10T09:00:00Z"
    }
  ],
  "meta": {
    "request_id": "req_efg123",
    "timestamp": "2024-01-15T10:30:00Z",
    "next_cursor": null,
    "has_more": false
  }
}
```

### Response Fields

<ResponseField name="id" type="string">
  The unique identifier for the webhook.
</ResponseField>

<ResponseField name="url" type="string">
  The HTTPS endpoint PathPilot sends event payloads to.
</ResponseField>

<ResponseField name="events" type="array">
  The list of event types this webhook is subscribed to.
</ResponseField>

<ResponseField name="status" type="string">
  `active` if PathPilot is delivering events to this webhook, or `disabled` if it has been automatically paused after repeated delivery failures.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the webhook was registered.
</ResponseField>

## Create a Webhook

Register a new webhook endpoint to receive events from your workspace.

```http
POST /v1/webhooks
```

### Request Body

<ParamField body="url" type="string" required>
  The HTTPS URL PathPilot should send event payloads to. Must use `https://`. PathPilot validates that the URL is reachable before saving the webhook.
</ParamField>

<ParamField body="events" type="array" required>
  An array of event type strings to subscribe to. Must contain at least one entry. Use `["*"]` to subscribe to all current and future event types.
</ParamField>

<ParamField body="secret" type="string">
  An optional custom secret used to sign webhook payloads. If omitted, PathPilot generates a cryptographically random secret for you. The secret is returned only in this response — store it securely in your secrets manager.
</ParamField>

### Example Request

```bash
curl -X POST https://api.pathpilot.com/v1/webhooks \
  -H "Authorization: Bearer pp_live_xxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://your-app.example.com/webhooks/pathpilot",
    "events": ["control.status_changed", "workflow.run_completed", "report.generated"],
    "secret": "my_custom_webhook_secret_32chars_min"
  }'
```

### Example Response

```json
{
  "data": {
    "id": "wbh_9sGz2mBv",
    "url": "https://your-app.example.com/webhooks/pathpilot",
    "events": ["control.status_changed", "workflow.run_completed", "report.generated"],
    "secret": "my_custom_webhook_secret_32chars_min",
    "status": "active",
    "created_at": "2024-01-15T11:00:00Z"
  },
  "meta": {
    "request_id": "req_hij456",
    "timestamp": "2024-01-15T11:00:00Z"
  }
}
```

The `secret` field is included **only in this response**. Copy it and store it in your application's secrets manager immediately — PathPilot does not expose the secret value again after creation.

## Delete a Webhook

Permanently remove a webhook from your workspace. PathPilot immediately stops delivering events to the registered URL. Any in-flight deliveries may still arrive within a short window after deletion.

```http
DELETE /v1/webhooks/{webhook_id}
```

### Path Parameters

<ParamField path="webhook_id" type="string" required>
  The unique ID of the webhook to delete.
</ParamField>

### Example Request

```bash
curl -X DELETE https://api.pathpilot.com/v1/webhooks/wbh_9sGz2mBv \
  -H "Authorization: Bearer pp_live_xxxxxxxxxxxx"
```

A successful request returns `204 No Content`.

## Test a Webhook

Send a test event payload to a registered webhook to verify that your endpoint is reachable and processing payloads correctly. This fires a synthetic `control.status_changed` event regardless of which event types the webhook is subscribed to.

```http
POST /v1/webhooks/{webhook_id}/test
```

### Path Parameters

<ParamField path="webhook_id" type="string" required>
  The unique ID of the webhook to test.
</ParamField>

### Example Request

```bash
curl -X POST https://api.pathpilot.com/v1/webhooks/wbh_4kRp7nQm/test \
  -H "Authorization: Bearer pp_live_xxxxxxxxxxxx"
```

### Example Response

```json
{
  "data": {
    "webhook_id": "wbh_4kRp7nQm",
    "delivery_id": "dlv_7tJn4pXc",
    "status": "delivered",
    "response_code": 200,
    "delivered_at": "2024-01-15T11:05:00Z"
  },
  "meta": {
    "request_id": "req_klm789",
    "timestamp": "2024-01-15T11:05:00Z"
  }
}
```

<ResponseField name="delivery_id" type="string">
  A unique ID for this test delivery attempt. Use it to correlate the test request with logs on your endpoint.
</ResponseField>

<ResponseField name="status" type="string">
  `delivered` if your endpoint responded with a `2xx` status code, or `failed` if it did not respond or returned an error.
</ResponseField>

<ResponseField name="response_code" type="integer">
  The HTTP status code your endpoint returned. PathPilot expects `2xx` for a successful delivery.
</ResponseField>

<ResponseField name="delivered_at" type="string">
  ISO 8601 timestamp of when the test payload was sent.
</ResponseField>
