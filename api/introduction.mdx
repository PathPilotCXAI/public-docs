The PathPilot REST API gives you full programmatic access to your compliance data. Use it to integrate PathPilot into your existing workflows, automate evidence collection, sync user rosters, trigger compliance reports, and build custom dashboards on top of your SOC 2 posture. Every action available in the PathPilot dashboard is also available through the API.

## Base URL

All API requests are made over HTTPS to the following base URL. Any request sent over plain HTTP will be rejected.

```text
https://api.pathpilot.com/v1
```

## Authentication

The PathPilot API uses API keys for authentication. Pass your API key as a Bearer token in the `Authorization` header of every request. Requests without a valid key return a `401 Unauthorized` response.

See the [Authentication guide](/api/authentication) for instructions on creating and managing your API keys.

## Request Format

For endpoints that accept a request body (`POST`, `PATCH`), send JSON and set the `Content-Type` header accordingly.

```bash
curl -X POST https://api.pathpilot.com/v1/users/invite \
  -H "Authorization: Bearer pp_live_xxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"email": "alex@example.com", "role": "editor"}'
```

## Response Format

All responses are returned as JSON. Successful responses wrap the primary payload in a `data` key alongside a `meta` object that contains request tracing information. You can use the `request_id` when contacting PathPilot support to diagnose any issue quickly.

```json
{
  "data": { "..." },
  "meta": {
    "request_id": "req_abc123",
    "timestamp": "2024-01-15T10:30:00Z"
  }
}
```

## Pagination

List endpoints use cursor-based pagination. Pass a `cursor` query parameter to retrieve the next page of results. The response's `meta` object includes `next_cursor` and `has_more` fields to help you iterate through large collections without missing or duplicating records.

```bash
# Fetch the first page
curl "https://api.pathpilot.com/v1/users?limit=25" \
  -H "Authorization: Bearer pp_live_xxxxxxxxxxxx"

# Fetch the next page using the cursor from the previous response
curl "https://api.pathpilot.com/v1/users?limit=25&cursor=cur_xyz789" \
  -H "Authorization: Bearer pp_live_xxxxxxxxxxxx"
```

A paginated response's `meta` block looks like this:

```json
{
  "data": ["..."],
  "meta": {
    "request_id": "req_abc123",
    "timestamp": "2024-01-15T10:30:00Z",
    "next_cursor": "cur_xyz789",
    "has_more": true
  }
}
```

When `has_more` is `false`, you have retrieved all available records. Do not pass a `cursor` value when it is absent or `null`.

## Rate Limits

PathPilot enforces rate limits to ensure reliable service for all customers. Limits are applied per API key on a rolling one-minute window.

| Plan       | Requests per minute |
|------------|---------------------|
| Pro        | 1,000               |
| Enterprise | 5,000               |

When you exceed your limit, the API returns a `429 Too Many Requests` response. The response includes a `Retry-After` header indicating the number of seconds you must wait before retrying. Build your integration to respect this header and implement exponential backoff for resilience.

<Note>
  API access is available on the **Pro** and **Enterprise** plans. If you are on the Starter plan, upgrade your workspace in **Settings → Billing** to unlock API keys.
</Note>
