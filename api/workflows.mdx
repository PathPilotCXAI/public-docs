The Workflows API lets you build, configure, and trigger automation inside PathPilot programmatically. Workflows connect compliance events — like a new evidence upload or a failed control check — to automated actions such as notifying a Slack channel, creating a Jira ticket, or running an evidence collection script. Use this API to manage workflows as code and integrate them into your deployment pipelines.

## List Workflows

Retrieve a paginated list of all workflows in your workspace.

```
GET /v1/workflows
```

### Query Parameters

<ParamField query="status" type="string">
  Filter workflows by their current status. Accepted values: `active`, `inactive`.
</ParamField>

<ParamField query="limit" type="integer" default="20">
  The maximum number of workflows to return per page. Accepted range: `1`–`100`.
</ParamField>

<ParamField query="cursor" type="string">
  A pagination cursor from `meta.next_cursor` in a previous response.
</ParamField>

### Example Request

```bash
curl "https://api.pathpilot.com/v1/workflows?status=active&limit=10" \
  -H "Authorization: Bearer pp_live_xxxxxxxxxxxx"
```

### Example Response

```json
{
  "data": [
    {
      "id": "wfl_3mHj8kRp",
      "name": "Weekly Access Review Reminder",
      "trigger": {
        "type": "schedule",

      },
      "status": "active",
      "last_run_at": "2024-01-15T09:00:00Z"
    },
    {
      "id": "wfl_7qNv2cBs",
      "name": "Notify on Evidence Upload",
      "trigger": {
        "type": "event",
        "event_type": "evidence.uploaded"
      },
      "status": "active",
      "last_run_at": "2024-01-14T16:22:45Z"
    }
  ],
  "meta": {
    "request_id": "req_mno345",
    "timestamp": "2024-01-15T10:30:00Z",
    "next_cursor": null,
    "has_more": false
  }
}
```

### Response Fields

<ResponseField name="id" type="string">
  The unique identifier for the workflow.
</ResponseField>

<ResponseField name="name" type="string">
  The human-readable name of the workflow.
</ResponseField>

<ResponseField name="trigger" type="object">
  The trigger configuration for this workflow. Contains a `type` field (`schedule` or `event`) and either a `cron` expression or an `event_type` string.
</ResponseField>

<ResponseField name="status" type="string">
  Whether the workflow is currently `active` or `inactive`. Inactive workflows do not run automatically but can still be triggered manually.
</ResponseField>

<ResponseField name="last_run_at" type="string">
  ISO 8601 timestamp of the most recent workflow execution. Returns `null` if the workflow has never been run.
</ResponseField>

## Get a Workflow

Retrieve the full configuration of a single workflow by its ID, including its trigger and complete actions list.

```
GET /v1/workflows/{workflow_id}
```

### Path Parameters

<ParamField path="workflow_id" type="string" required>
  The unique ID of the workflow to retrieve.
</ParamField>

### Example Request

```bash
curl https://api.pathpilot.com/v1/workflows/wfl_3mHj8kRp \
  -H "Authorization: Bearer pp_live_xxxxxxxxxxxx"
```

## Create a Workflow

Define a new workflow by specifying its trigger and a sequence of actions to execute. Newly created workflows are `active` by default.

```
POST /v1/workflows
```

### Request Body

<ParamField body="name" type="string" required>
  A descriptive name for the workflow. This appears in the PathPilot dashboard and in run logs.
</ParamField>

<ParamField body="trigger" type="object" required>
  An object that defines what initiates the workflow. Must include a `type` field.

  - If `type` is `schedule`, also include a `cron` field containing a valid cron expression (for example, `"0 9 * * MON"`).
  - If `type` is `event`, also include an `event_type` field matching one of the [supported event types](/api/webhooks#supported-events).
</ParamField>

<ParamField body="actions" type="array" required>
  An ordered array of action objects to execute when the workflow is triggered. Each action must include a `type` field (for example, `send_notification`, `create_ticket`, `run_script`) and a corresponding `config` object with action-specific parameters.
</ParamField>

### Example Request

```bash
curl -X POST https://api.pathpilot.com/v1/workflows \
  -H "Authorization: Bearer pp_live_xxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Quarterly Evidence Collection",
    "trigger": {
      "type": "schedule",
      "cron": "0 8 1 1,4,7,10 *"
    },
    "actions": [
      {
        "type": "send_notification",
        "config": {
          "channel": "slack",
          "message": "Quarterly evidence collection has started."
        }
      },
      {
        "type": "run_script",
        "config": {
          "script_id": "scr_9pLv5wT2"
        }
      }
    ]
  }'
```

### Example Response

```json
{
  "data": {
    "id": "wfl_1sKw4dYn",
    "name": "Quarterly Evidence Collection",
    "trigger": {
      "type": "schedule",
      "cron": "0 8 1 1,4,7,10 *"
    },
    "actions": [
      {
        "type": "send_notification",
        "config": {
          "channel": "slack",
          "message": "Quarterly evidence collection has started."
        }
      },
      {
        "type": "run_script",
        "config": {
          "script_id": "scr_9pLv5wT2"
        }
      }
    ],
    "status": "active",

    "last_run_at": null
  },
  "meta": {
    "request_id": "req_pqr678",
    "timestamp": "2024-01-15T11:00:00Z"
  }
}
```

## Update a Workflow

Modify an existing workflow's name, trigger, actions, or status. Only the fields you include in the request body are updated — omitted fields retain their current values.

```
PATCH /v1/workflows/{workflow_id}
```

### Path Parameters

<ParamField path="workflow_id" type="string" required>
  The unique ID of the workflow to update.
</ParamField>

### Request Body

<ParamField body="name" type="string">
  A new name for the workflow.
</ParamField>

<ParamField body="trigger" type="object">
  A replacement trigger configuration. Replaces the entire existing trigger object.
</ParamField>

<ParamField body="actions" type="array">
  A replacement actions list. Replaces all existing actions in the workflow.
</ParamField>

<ParamField body="status" type="string">
  Set to `active` to enable the workflow or `inactive` to pause it without deleting it.
</ParamField>

### Example Request

```bash
curl -X PATCH https://api.pathpilot.com/v1/workflows/wfl_1sKw4dYn \
  -H "Authorization: Bearer pp_live_xxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"status": "inactive"}'
```

## Delete a Workflow

Permanently delete a workflow and its run history. This action cannot be undone. If you want to stop a workflow from running without deleting it, set its `status` to `inactive` instead.

```
DELETE /v1/workflows/{workflow_id}
```

### Path Parameters

<ParamField path="workflow_id" type="string" required>
  The unique ID of the workflow to delete.
</ParamField>

### Example Request

```bash
curl -X DELETE https://api.pathpilot.com/v1/workflows/wfl_1sKw4dYn \
  -H "Authorization: Bearer pp_live_xxxxxxxxxxxx"
```

A successful request returns `204 No Content`.

## Trigger a Workflow Manually

Execute a workflow immediately, outside of its configured schedule or event trigger. This is useful for testing a workflow or running a one-off execution without modifying the workflow's trigger configuration.

```
POST /v1/workflows/{workflow_id}/run
```

### Path Parameters

<ParamField path="workflow_id" type="string" required>
  The unique ID of the workflow to trigger.
</ParamField>

### Example Request

```bash
curl -X POST https://api.pathpilot.com/v1/workflows/wfl_3mHj8kRp/run \
  -H "Authorization: Bearer pp_live_xxxxxxxxxxxx"
```

### Example Response

```json
{
  "data": {
    "run_id": "run_6tFm9nGc",
    "workflow_id": "wfl_3mHj8kRp",
    "status": "running",
    "triggered_at": "2024-01-15T11:15:00Z"
  },
  "meta": {
    "request_id": "req_stu901",
    "timestamp": "2024-01-15T11:15:00Z"
  }
}
```

<ResponseField name="run_id" type="string">
  The unique ID for this specific execution. Use this to look up run logs in the PathPilot dashboard or to correlate with webhook events of type `workflow.run_completed`.
</ResponseField>

<ResponseField name="status" type="string">
  The current status of the run. Initially `running`; transitions to `completed` or `failed` once execution finishes.
</ResponseField>

<ResponseField name="triggered_at" type="string">
  ISO 8601 timestamp of when this run was initiated.
</ResponseField>
