The Users API lets you manage the members of your PathPilot workspace programmatically. Use it to sync your identity provider with PathPilot, automate onboarding and offboarding, enforce role policies, and audit workspace membership. All endpoints operate on the workspace associated with your API key.

## List Users

Retrieve a paginated list of all users in your workspace. Filter by role to narrow results.

```
GET /v1/users
```

### Query Parameters

<ParamField query="role" type="string">
  Filter users by their workspace role. Accepted values: `admin`, `editor`, `auditor`, `viewer`. Omit this parameter to return users of all roles.
</ParamField>

<ParamField query="limit" type="integer" default="20">
  The maximum number of users to return per page. Accepted range: `1`–`100`.
</ParamField>

<ParamField query="cursor" type="string">
  A pagination cursor returned in `meta.next_cursor` from a previous response. Pass this value to retrieve the next page of results.
</ParamField>

### Example Request

```bash
curl "https://api.pathpilot.com/v1/users?role=editor&limit=25" \
  -H "Authorization: Bearer pp_live_xxxxxxxxxxxx"
```

### Example Response

```json
      "last_login_at": "2024-01-14T17:42:10Z"
    },
    {
      "id": "usr_9pLv5wT2",
      "email": "morgan@example.com",
      "name": "Morgan Lee",
      "role": "editor",
      "created_at": "2023-12-05T14:20:00Z",
      "last_login_at": "2024-01-15T08:05:33Z"
    }
  ],
  "meta": {
    "request_id": "req_abc123",
    "timestamp": "2024-01-15T10:30:00Z",
    "next_cursor": "cur_xyz789",
    "has_more": true
  }
}
```

### Response Fields

<ResponseField name="id" type="string">
  The unique identifier for the user. Use this ID in subsequent requests that require a `user_id` path parameter.
</ResponseField>

<ResponseField name="email" type="string">
  The user's email address.
</ResponseField>

<ResponseField name="name" type="string">
  The user's display name as set in their profile.
</ResponseField>

<ResponseField name="role" type="string">
  The user's current workspace role: `admin`, `editor`, `auditor`, or `viewer`.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the user was added to the workspace.
</ResponseField>

<ResponseField name="last_login_at" type="string">
  ISO 8601 timestamp of the user's most recent login. Returns `null` if the user has never signed in.
</ResponseField>

## Get a User

Retrieve a single user by their ID.

```
GET /v1/users/{user_id}
```

### Path Parameters

<ParamField path="user_id" type="string" required>
  The unique ID of the user to retrieve (for example, `usr_4kQm2nR7`).
</ParamField>

### Example Request

```bash
curl https://api.pathpilot.com/v1/users/usr_4kQm2nR7 \
  -H "Authorization: Bearer pp_live_xxxxxxxxxxxx"
```

### Example Response

```json
{
  "data": {
    "id": "usr_4kQm2nR7",

    "role": "editor",
```

## Invite a User

Send an email invitation to a new user and assign them a role in your workspace. The invited user receives an email prompting them to accept the invitation and create or sign in to their PathPilot account.

```
POST /v1/users/invite
```

### Request Body

<ParamField body="email" type="string" required>
  The email address of the person to invite. An invitation email is sent to this address.
</ParamField>

<ParamField body="role" type="string" required>
  The workspace role to assign upon acceptance. Must be one of `admin`, `editor`, `auditor`, or `viewer`.
</ParamField>

<ParamField body="teams" type="array">
  An optional array of team IDs to assign the user to upon accepting the invitation. You can update team membership later using the Teams API.
</ParamField>

### Example Request

```bash
curl -X POST https://api.pathpilot.com/v1/users/invite \
  -H "Authorization: Bearer pp_live_xxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "email": "jordan@example.com",
    "role": "auditor",
    "teams": ["team_8rNk3mW1"]
  }'
```

### Example Response

```json
{
  "data": {
    "id": "inv_2xBn7qP4",
    "email": "jordan@example.com",
    "role": "auditor",
    "teams": ["team_8rNk3mW1"],
    "status": "pending",
    "invited_at": "2024-01-15T10:35:00Z",
    "expires_at": "2024-01-22T10:35:00Z"
  },
  "meta": {
    "request_id": "req_ghi789",
    "timestamp": "2024-01-15T10:35:00Z"
  }
}
```

The response returns `201 Created` with an invite object. The `status` field will be `pending` until the user accepts the invitation. Invitations expire after 7 days; resend by calling this endpoint again with the same email address.

## Update a User's Role

Change the workspace role of an existing user. This takes effect immediately — the user's permissions update the next time they make a request or refresh their session.

```
PATCH /v1/users/{user_id}
```

### Path Parameters

<ParamField path="user_id" type="string" required>
  The unique ID of the user to update.
</ParamField>

### Request Body

<ParamField body="role" type="string" required>
  The new role to assign. Must be one of `admin`, `editor`, `auditor`, or `viewer`.
</ParamField>

### Example Request

```bash
curl -X PATCH https://api.pathpilot.com/v1/users/usr_4kQm2nR7 \
  -H "Authorization: Bearer pp_live_xxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"role": "admin"}'
```

### Example Response

```json
{
  "data": {
    "id": "usr_4kQm2nR7",
    "email": "alex@example.com",
    "name": "Alex Rivera",
    "role": "admin",
    "created_at": "2023-11-01T09:00:00Z",
    "last_login_at": "2024-01-14T17:42:10Z"
  },
  "meta": {
    "request_id": "req_jkl012",
    "timestamp": "2024-01-15T10:40:00Z"
  }
}
```

## Remove a User

Remove a user from your workspace. This immediately revokes their access to all workspace resources. This action does not delete the user's PathPilot account — it only removes their membership from your workspace.

```
DELETE /v1/users/{user_id}
```

### Path Parameters

<ParamField path="user_id" type="string" required>
  The unique ID of the user to remove.
</ParamField>

### Example Request

```bash
curl -X DELETE https://api.pathpilot.com/v1/users/usr_4kQm2nR7 \
  -H "Authorization: Bearer pp_live_xxxxxxxxxxxx"
```

A successful request returns `204 No Content` with an empty response body. If the user ID does not exist, the API returns `404 Not Found`.
