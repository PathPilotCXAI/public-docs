The most time-consuming part of SOC2 compliance isn't understanding the requirements — it's collecting and organizing the evidence that proves you meet them. PathPilot integrations connect directly to the tools your organization already uses, pulling relevant logs, access records, and configuration data automatically and mapping them to the appropriate controls. Instead of manually exporting reports from a dozen different systems, you configure a connection once and let PathPilot do the collection work continuously.

## Connecting an Integration

Setting up a new integration takes just a few minutes. PathPilot walks you through the authorization process and lets you choose exactly which data to sync.

<Steps>
  <Step title="Open the Integrations Settings">
    Navigate to **Settings → Integrations** in the left sidebar. You'll see a catalog of all available integrations organized by category, with connection status indicators showing which ones are already active.
  </Step>
  <Step title="Find the Integration">
    Locate the integration you want to connect — either by browsing the category tiles or using the search bar. Click the integration card to open its detail view, which shows what data PathPilot will collect and which controls it maps to.
  </Step>
  <Step title="Click Connect">
    Click the **Connect** button on the integration detail page. PathPilot will begin the authorization flow for that service.
  </Step>
  <Step title="Authorize Access">
    Depending on the integration, you'll either be redirected to the provider's OAuth consent screen (for services like Okta, GitHub, and Google Workspace) or prompted to enter API credentials such as an access key and secret (for services like AWS). Follow the on-screen instructions to grant PathPilot the required read permissions. PathPilot only requests the minimum scopes needed for evidence collection — it does not request write access to your systems.
  </Step>
  <Step title="Select Which Data to Sync">
    After authorization succeeds, PathPilot presents a configuration screen where you can select which data types to pull, which controls to map collected evidence to, and how frequently PathPilot should sync. Confirm your selections and click **Save**. PathPilot will run an initial sync immediately and then continue on your chosen schedule.
  </Step>
</Steps>

## What Data is Collected

Each integration targets the specific evidence types that are most relevant for SOC2 controls. Here's what PathPilot collects from the most commonly used integrations:

| Integration | Evidence Collected |
|---|---|
| **AWS CloudTrail** | API activity logs showing who performed what actions in your AWS environment, used as evidence for monitoring and audit logging controls. |
| **AWS IAM** | User and role permission configurations, used as evidence for least-privilege access controls and quarterly access reviews. |
| **Okta** | User provisioning and deprovisioning events, MFA enrollment rates, and login activity, mapped to access control and user lifecycle controls. |
| **GitHub** | Repository access lists, pull request review records, and branch protection configurations, used as evidence for change management and code review controls. |
| **Google Workspace** | Admin activity logs and user account lifecycle events, mapped to access control and termination procedure controls. |
| **BambooHR / Rippling / Gusto** | New hire and termination records, used to verify that access provisioning and deprovisioning procedures are being followed. |

## Managing Integrations

Once an integration is connected, you can monitor and manage it from the **Settings → Integrations** page.

- **Sync status** — Each integration card shows the last successful sync time and whether the most recent sync completed without errors.
- **Re-authorizing** — If an integration's credentials expire or access is revoked in the source system, PathPilot will surface an alert. Click **Re-authorize** on the integration card to initiate a fresh OAuth flow or update your API credentials without losing your existing configuration.
- **Disconnecting** — To remove an integration, click the integration card and select **Disconnect**. This stops future evidence collection but does not delete evidence already collected and attached to controls.

<Warning>
Revoking or rotating integration credentials in the source system (for example, deleting an AWS access key or deauthorizing an OAuth app in Okta) without immediately re-authorizing PathPilot will cause a gap in your automated evidence collection. If automated evidence stops flowing in, controls that depend on that integration may show as Failing and trigger workflow alerts. Always re-authorize the PathPilot connection immediately after rotating credentials.
</Warning>

<Note>
If you need to connect a tool that isn't in PathPilot's native integration catalog, you can push data into PathPilot using the **Webhook API**. Any system capable of sending an HTTP POST request can deliver evidence payloads, trigger workflow events, and update control statuses programmatically. See the [Webhook API reference](/api/webhooks) for payload schema and authentication details.
</Note>
