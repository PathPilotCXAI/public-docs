Manual compliance work doesn't scale. Chasing down evidence, reminding control owners to complete reviews, and updating control statuses by hand introduces delays and human error — exactly the kind of gaps that auditors flag. PathPilot Workflows let you encode your compliance processes as automated sequences that run on a schedule or in response to events, so your program stays current without constant manual effort.

## What is a Workflow?

A workflow is a set of automated actions that PathPilot executes when a specific trigger condition is met. Workflows replace repetitive manual tasks — like emailing a team member to upload evidence every month — with reliable, auditable automation.

Workflows support two types of triggers:

- **Schedule triggers** run on a recurring cadence you define: daily, weekly, or monthly. Use these for routine evidence pulls, periodic access reviews, and recurring reminders.
- **Event triggers** fire in response to something happening in PathPilot or a connected integration: a new user being added in Okta, a control status changing to Failing, an integration sync completing, or a webhook payload arriving from an external system.

Once a trigger fires, PathPilot executes the workflow's actions in sequence — collecting evidence, sending notifications, creating tasks, and updating records — all without requiring anyone to intervene manually.

## Creating a Custom Workflow

If the built-in templates don't cover your use case, you can build a workflow from scratch in just a few steps.

<Steps>
  <Step title="Open the Workflow Builder">
    Navigate to **Workflows** in the left sidebar and click **New Workflow**. Give your workflow a descriptive name (e.g., "Monthly IAM Evidence Collection") so it's easy to identify later.
  </Step>
  <Step title="Choose a Trigger">
    Select either **Schedule** or **Event** as your trigger type.
    - For a **Schedule** trigger, choose the frequency (daily, weekly, or monthly) and set the time and timezone.
    - For an **Event** trigger, choose the event source (e.g., PathPilot, Okta, GitHub) and select the specific event that should fire the workflow (e.g., "Control status changed to Failing").
  </Step>
  <Step title="Add Actions">
    Click **Add Action** and choose from the available action types. You can chain multiple actions together — for example, collect evidence from AWS, then notify the control owner, then create a task for review. Actions execute in the order you define them.
  </Step>
  <Step title="Set Conditions and Filters">
    Optionally, add conditions to limit when the workflow runs. For example, you can restrict an action to fire only when a control belongs to a specific framework, is owned by a certain team, or has been in a Failing state for more than seven days.
  </Step>
  <Step title="Activate the Workflow">
    Review your workflow configuration and click **Activate**. PathPilot will begin executing the workflow on its next scheduled trigger or the next time its event condition is met. You can pause or deactivate a workflow at any time from the Workflows list.
  </Step>
</Steps>

## Workflow Actions

Each workflow can include one or more of the following action types:

| Action | Description |
|---|---|
| **Collect Evidence** | Pulls evidence artifacts from a connected integration and attaches them to a specified control or control group. |
| **Send Notification** | Sends an email or Slack message to a specified user, team, or control owner. Message content supports dynamic variables like control name, due date, and status. |
| **Create Task** | Creates a new task in PathPilot and assigns it to a specified user or role, with a configurable due date and priority level. |
| **Update Control Status** | Programmatically sets a control's status to Not Started, In Progress, Passing, or Failing based on the workflow's logic. |
| **Call Webhook** | Sends an HTTP POST request to an external URL with a configurable payload. Use this to trigger actions in tools that PathPilot doesn't natively support. |

## Monitoring Workflow Runs

Every workflow execution is logged so you can verify that automation is working as expected and troubleshoot any failures.

To view run history, navigate to **Workflows**, find the workflow you want to inspect, and click **View Runs**. The run history table shows:

- **Run date and time** — When the workflow was triggered.
- **Trigger type** — Whether the run was triggered by a schedule or an event.
- **Status** — Whether the run succeeded, partially succeeded, or failed.
- **Actions executed** — A step-by-step breakdown of each action in the run, with its individual success or failure status.
- **Logs** — Detailed log output for each action, including API responses from integrations and any error messages.

If a run fails, PathPilot will notify the workflow's creator via email and mark the associated control or task for review. You can manually re-run a failed workflow from the run history view after resolving the underlying issue.
