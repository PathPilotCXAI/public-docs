PathPilot supports multiple authentication methods to fit your organization's security requirements. Whether you're logging in through the web app, enforcing single sign-on across your team, or connecting third-party tools via the API, this guide walks you through every option available and the best practices for keeping your credentials secure.

## Logging In

To access PathPilot, navigate to [app.pathpilot.com](https://app.pathpilot.com) in your browser. Enter your registered email address and password, then click **Sign In**.

If your organization has SSO enabled, you'll see a **Sign in with SSO** button on the login page. Click it, enter your work email address, and you'll be redirected to your identity provider to complete authentication. You won't need to enter a PathPilot-specific password when SSO is active.

If you've forgotten your password, click **Forgot password?** on the login screen and follow the instructions sent to your email to reset it.

## Single Sign-On (SSO)

PathPilot supports SAML 2.0-based Single Sign-On, allowing your team to authenticate through your existing identity provider rather than managing separate PathPilot passwords. SSO is available on the **Pro** and **Enterprise** plans.

To enable SSO for your organization, go to **Settings → SSO** and follow the configuration steps for your identity provider. PathPilot natively supports the following IdPs:

- **Okta**
- **Azure Active Directory (Azure AD)**
- **Google Workspace**

Any SAML 2.0-compliant identity provider can also be configured manually using the metadata URL or XML provided in the SSO settings page. For detailed setup instructions, including attribute mapping and certificate configuration, see the [Access Controls](/security/access-controls) guide.

Once SSO is configured and enabled, all users in your organization will be required to authenticate through your IdP. Existing email/password sessions will be invalidated at next login.

## Multi-Factor Authentication

Multi-factor authentication (MFA) adds an extra layer of security to your PathPilot account by requiring a second verification step at login. You can enable MFA on your personal account at any time, regardless of your plan.

To enable MFA:

1. Go to **Settings → Profile → Security**.
2. Under **Two-Factor Authentication**, click **Enable**.
3. Choose your preferred method:
   - **Authenticator App (TOTP)** — scan the QR code with an app like Google Authenticator, Authy, or 1Password, then enter the 6-digit code to confirm setup.
   - **Hardware Security Key (WebAuthn)** — register a physical key such as a YubiKey by following the on-screen prompts.
4. Save your recovery codes in a secure location. These allow you to regain access if you lose your MFA device.

Once enabled, PathPilot will prompt you for your second factor each time you log in from a new device or browser session. Organization Admins can enforce MFA for all members via **Settings → Security Policy**.

## API Keys

API keys allow you to authenticate programmatic requests to the PathPilot API — for example, when building integrations, automating evidence uploads, or querying compliance data from external tools.

To create a new API key:

1. Go to **Settings → API Keys**.
2. Click **New Key**.
3. Enter a descriptive name for the key (e.g., `ci-pipeline-integration` or `evidence-uploader`).
4. Optionally, set an expiry date to automatically rotate the key on a schedule.
5. Click **Create Key**.
6. Copy the key immediately — it is shown only once.

Use your API key as a Bearer token in the `Authorization` header of every API request:

```bash
curl -X GET https://api.pathpilot.com/v1/users \
  -H "Authorization: Bearer YOUR_API_KEY"
```

PathPilot will return a `401 Unauthorized` response for any request with a missing, invalid, or revoked API key.

## Revoking API Keys

If an API key is compromised, no longer needed, or has reached the end of its intended lifecycle, you should revoke it immediately to prevent unauthorized access.

To revoke a key, go to **Settings → API Keys**, find the key you want to remove, and click **Revoke** next to it. Revocation takes effect instantly — any in-flight requests using that key will begin failing immediately. Revoked keys cannot be restored; if you need continued access, create a new key.

<Warning>
  API keys are displayed **only once** at the time of creation. PathPilot does not store the plaintext key and cannot show it to you again. Always copy your key immediately and store it securely in a secrets manager such as AWS Secrets Manager, HashiCorp Vault, or your CI/CD platform's encrypted environment variables.
</Warning>

<Tip>
  Create a separate API key for each integration or service that connects to PathPilot. This way, if one key is compromised or needs to be rotated, you can revoke it without disrupting your other integrations. Descriptive key names make it easy to identify which key belongs to which system.
</Tip>
